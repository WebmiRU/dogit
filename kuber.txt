как мне из кластера кубернетиса - получить доступ к локальному веб-серверу, который работает на той же машине, что и k3s-кластер?

Да. Если k3s запущен на той же физической машине, где локальный веб-сервер, то способ зависит от того, где именно слушает веб-сервер.
Самый простой вариант

Допустим, на хосте:

curl http://127.0.0.1:8080

работает.

Из Pod это не сработает:

curl http://127.0.0.1:8080

потому что 127.0.0.1 внутри Pod — это сам Pod, а не хост.

В k3s можно обратиться к хосту через его адрес в сети. Сначала посмотри:

ip addr

например, хост имеет:

192.168.1.50

Тогда из Pod:

curl http://192.168.1.50:8080

Но есть важный нюанс: веб-сервер должен слушать не только 127.0.0.1, а интерфейс, доступный из Pod-сети.

Например:

ss -lntp | grep 8080

Если видишь:

127.0.0.1:8080

то Pod к нему обычно не достучится.

Нужно, чтобы сервер слушал, например:

0.0.0.0:8080

или конкретный IP хоста.
Если хочешь нормальное Kubernetes-имя

Можно создать Service, который указывает на IP самого хоста:

apiVersion: v1
kind: Service
metadata:
  name: local-web
spec:
  ports:
    - port: 8080
      targetPort: 8080
  type: ClusterIP
---
apiVersion: v1
kind: Endpoints
metadata:
  name: local-web
subsets:
  - addresses:
      - ip: 192.168.1.50
    ports:
      - port: 8080

После этого из любого Pod:

curl http://local-web:8080

Это уже довольно удобный вариант.
А если веб-сервер слушает только localhost

Если тебе принципиально нужно достучаться именно до:

127.0.0.1:8080

хоста, то есть несколько вариантов — например hostNetwork: true для Pod:

spec:
  hostNetwork: true

Тогда:

curl http://127.0.0.1:8080

из контейнера будет обращаться к network namespace хоста.

Но я бы для обычного приложения так не делал — hostNetwork имеет побочные эффекты и менее изолирован.

Если ты сейчас только ставишь локальный k3s для разработки, я бы рекомендовал другой вариант: сделать доступ Pod → host через специальный DNS/IP, чтобы можно было писать, например:

http://host.docker.internal:8080

или аналогичный адрес для Kubernetes.

Могу показать конкретно для k3s, как сделать host.k3s → IP твоей машины, чтобы любой Pod мог обращаться к локальным сервисам по нормальному имени.
